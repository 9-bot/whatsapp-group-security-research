Automating a WhatsApp Group Portfolio: Templates, Delegated Permissions and SLA Health Checks

Most companies never decide to run a portfolio of WhatsApp groups. They accumulate one. A sales lead opens a distributor group, support opens one per key account, marketing builds a customer community, and eventually an agency inherits the whole set under a monthly contract. At that point the useful question is no longer which bot to install. It is how to apply one rule set to dozens of groups without granting more access than each task needs.

This note reads the 9bot guide to WhatsApp group automation for business as a systems design problem: what runs where, under which identity, and how you prove it is still running.

The platform sets the boundary

Ivan Schroll's portfolio governance review (DOI 10.17605/OSF.IO/G6HF9) lays out the primitives. An ordinary group, including one opened from the Business app, holds up to 1,024 members, and its creator cannot be removed by anyone else. The Cloud API Groups API lets a business number own up to 10,000 groups, but each one is capped at 8 participants and people can join only through an invite link. Large customer and reseller communities therefore stay in ordinary groups, where the organisation has no native log of admin actions.

The same review is explicit about third party management tools. They operate with the permissions of the connected account. They cannot remove a group creator, have no visibility into groups that account never joined, and cannot bring back messages sent before the connection existed. They also become a supplier in the data processing chain, which calls for a contract and an entry in the processing record. Those limits define the trust boundary of any automation design.

Task to control mapping

Repeated task Manual operation Automated control in 9bot
Entry Someone clears the request queue between other jobs Approval rules with filters and a cap per day
First message Each admin improvises a greeting One standard welcome per group
Unwanted links Deleted if an admin happens to be online Link filter, banned words, strike counter
Recurring questions Staff retype the same answer Custom commands like .menu
Announcements Sent late or forgotten Recurring schedules across groups
Client reporting Screenshots pasted into slides Metrics exported to PDF

Read the table as a list of services, each with an owner and a failure mode. If the link filter is off in one group, that group is exposed even when forty others are fine. This is why the guide pushes reusable templates: configuration drift between groups is the quiet way a portfolio degrades.

Integrations go outbound only

When a group needs to reach another system, 9bot relies on commands that issue an outgoing HTTP request with GET, POST or PUT to your CRM, your ERP or an automation platform such as n8n or Make. The command to CRM integration guide states that 9bot exposes no URL for receiving webhooks. In network terms, you open no inbound port for the bot. Your endpoint authenticates the call, validates input and decides what a command may read or change.

Design each command with least privilege. A lookup should hit a read only route, a command that creates a record should be idempotent on the destination side, and nothing sensitive should be echoed back into a shared conversation. Credentials live in configuration, never in command text that members can see.

A portfolio manifest

Treat the portfolio as configuration you can diff. The layout below is meant for a repository you control; 9bot does not import it. Each field maps either to a control named in the guide or to the register proposed in the governance review.

portfolio: "<client or business unit>"
groups:
  - id: "<group name>"
    purpose: reseller_orders
    created_by_company_number: true
    company_admins: ["<ops number A>", "<ops number B>"]   # at least two
    template: b2b_default
    agency_admin_until: "<contract end date>"
templates:
  b2b_default:
    admission: { approval: filtered, daily_cap: "<n>" }
    welcome: standard_v1
    links: { mode: allowlist, domains: ["<company domain>"] }
    moderation: { banned_words: "<list ref>", strikes: enabled }
    commands:
      - trigger: ".menu"
        response: text
      - trigger: "/order"
        response: api
        method: GET
        endpoint: "<read-only order status route>"
    schedules: ["<recurring notice ref>"]
reporting:
  monthly_pdf: [active_members, inactive_7d, joins, exits, net_growth, peak_hours]
service_level:
  coverage_hours: "<window>"
  human_reply_target: "<time>"
  banned_content_removal_target: "<time>"
  campaign_approver: "<role>"

The agency_admin_until field encodes a point from the governance review: when an agency or partner contract ends, its admin rights should end with it. Two company admins per group close the path where WhatsApp picks a random member as admin after the last one leaves.

SLAs are health checks

The guide separates what automation covers from what the contract covers. Rules run continuously, while the service level defines coverage hours, the time to answer questions a bot cannot resolve, the time to take down banned content and who signs off on campaigns. Engineers will recognise the pattern. Turn each clause into a probe:

  1. Every group in the manifest still lists two company admins.
  2. The link filter and strike counter are active in each group.
  3. Scheduled notices fired in the last cycle without errors.
  4. Command calls to the CRM or ERP show success in the dashboard logs.
  5. The monthly PDF for each client was generated on time.

A failed probe is an incident with an owner, exactly like an expired certificate.

Identity and devices

Admin rights live on phone accounts, and the review notes that one account can link up to four companion devices. Every linked device is a place from which admin actions can be taken, so the device list belongs in the same periodic review as the admin list. The account takeover paper (DOI 10.17605/OSF.IO/HZUN5) explains the stakes: a single stolen verification code gives an attacker control of all groups that account runs. Two step verification on admin accounts is a baseline.

Evaluating vendors

When you compare group managers, ask questions that map to risk. Can moderation act with no admin online? Is there one panel with templates? Does each operator get individual access rather than a shared password? Can schedules recur across groups? Which metrics leave as PDF? Can a command call your systems? How is pricing structured? Does the vendor present itself as a Meta product? Third party tools are not Meta software, and a trial with a real group should come before any contract.

Conclusion

Automation at portfolio scale is mostly access design: one manifest, minimal permissions per command, outbound integrations and service levels expressed as checks. 9bot fills that execution role as a paid, independent product, testable for 7 days and unaffiliated with Meta.
